# Каталог картин по годам

## Задача

Программа хранит каталог картин (название, автор, год) и позволяет:
- искать картину по году;
- искать картину по названию;
- получать все картины в порядке возрастания года;
- получать обходы pre-order и post-order;
- удалять картину по названию;
- искать картины по автору.

## Структуры данных и алгоритмы

- **Бинарное дерево поиска (BST)** — упорядоченное хранение по году.
  Вставка, поиск и удаление — O(log n) в среднем.
  Симметричный обход даёт отсортированный по году список.
- **HashMap** — индекс по названию для поиска за O(1) в среднем.

Комбинация «дерево + хеш-таблица» — классический приём «индекс + дерево».

## Сложность

| Операция              | Время        | Память |
|-----------------------|--------------|--------|
| Вставка               | O(log n)     | O(n)   |
| Поиск по году         | O(log n)     | O(1)   |
| Поиск по названию     | O(1) среднее | O(1)   |
| Удаление              | O(log n)     | O(1)   |
| Обход по возрастанию  | O(n)         | O(n)   |
| Поиск по автору       | O(n)         | O(k)   |

В худшем случае (вырожденное дерево) BST деградирует до O(n).

## Архитектурное решение

**Почему BST + HashMap, а не только HashMap или только BST?**

- Только HashMap: нет упорядоченного обхода по годам.
- Только BST: поиск по названию — O(log n) и требует знания года.
- Гибрид: O(log n) по году + O(1) по названию, плюс сортированный обход.

## Альтернативы

- **Красно-чёрное дерево** (TreeMap) — даёт гарантированный O(log n), но не позволяет реализовать три обхода вручную.
- **Хеш-таблица для года** — теряется упорядоченность.
- **Список + сортировка** — вставка O(n), поиск O(log n) только после сортировки.
